# 多设备同步架构演进史

> 本文是**过去时**叙事：系统如何走到今天、每一步被什么驱动。当前态见 [current.md](current.md)，
> 每个决策的完整理由见 [adr/](adr/)。旧架构的原始说明冻结在 [archive/](archive/)。

## 演进时间线

| 阶段 | 数据模型版本 | 架构形态 | 驱动 |
|---|---|---|---|
| v1 | v4.2 及以前 | **整包快照**：全量数据一个 JSON，push/pull 整包覆盖 | 项目起步，最快跑通 |
| v2 | v4.5 | **记录级同步**：LWW + 墓碑 + 双时间戳 | 多设备并行编辑互相覆盖整包，冲突粒度太粗（ADR-0001~0004） |
| v3 | v4.5 加固 | 数据管理三层模型收敛、pull 复合游标分页、导入差集墓碑 | 实战中暴露的边角：后悔药语义、大数据量分页、覆盖复活（ADR-0005~0007） |
| v4 | v4.5 + 实时层 | **SSE 信令通道**：多设备触达分钟级 → 秒级 | 30s 防抖 + 5min 兜底的多设备体感延迟明显（ADR-0008） |
| v5 | 同上 | **调度双优化**：兜底轮询降频、前沿立即+后沿微批 | 轮询降级为保险、单设备编辑秒级上云（ADR-0009~0010） |

## v1 → v2：整包快照 → 记录级同步（2026-08 中旬）

v4.2 时代服务端只有一张 `snapshots` 表（每用户一行，整包 JSON）。两台设备并行使用时，
后推的整包直接覆盖前推的——A 刚建的任务会被 B 的旧整包抹掉，冲突粒度是"整个数据集"，
自用双设备也撑不住。

v4.5 重构为记录级：每条数据独立成行（`records` 表，主键 `(user_id, collection, record_id)`），
服务端逐条 LWW 裁决；客户端以基线 diff 出变更集上行。配套四个子决策：
双时间戳分工（ADR-0002）、settings 字段级记录化（ADR-0003）、apiKey 永不上云（ADR-0004）、
墓碑传播。服务端一次性迁移：旧 snapshots 拆包成 records（每用户至多执行一次，拆完清空快照表，
表结构保留作回滚线索）。

这一步确立了至今不变的架构底座：**服务端是带账号的哑记录仓库，不懂业务字段**。

## v2 → v3：实战加固（2026-08 下旬）

- **数据管理三层模型收敛**（ADR-0005）：删掉"本机保护快照层"，职责定死——localStorage 管用、
  同步管网、导出文件管历史。后悔药统一为事先导出的备份文件。
- **pull 复合游标分页**（ADR-0006）：push 整批共用同一 recv_time 形成大平局组，
  仅按 recv_time 翻页会组内原地踏步死循环，必须以 record_id 在组内推进。
- **导入覆盖语义与差集墓碑**（ADR-0007）：文件导入确立"备份为准"整体覆盖语义，
  差集墓碑防云端旧记录复活；2026-08-28 单测揪出复活记录被旧墓碑反向覆盖的 bug 并修复。

同期补齐前端同步/删除语义单测（fetch stub 驱动真实链路，21 例），为后续实时层改造提供安全网。

## v3 → v4：SSE 实时信令（2026-08-28）

多设备间感知延迟 = 对方设备的推送节奏（30s 防抖 ~ 5min 兜底），双设备切换体感明显。

方案选型（业内四路线对照：信令+拉取 / 通道直推数据 / 同步引擎框架 / CRDT）：
本系统是**单用户多设备 + 零依赖服务器 + LWW 已验证**形态，维持"信令 + 增量拉取"路线
（IMAP IDLE / CalDAV Push / CloudKit change token 同脉），只加一条**不带数据的裸信令通道**：
合并路径保持 pull 唯一，信令可丢可重，丢了退化为轮询语义。

工程要点：EventSource 无法带 Authorization 头 → 一次性短时票据认证；
`x-sync-tag` 排除发起设备自身，不产生自唤回拉；`X-Accel-Buffering: no` 逐流穿透 nginx。

## v4 → v5：调度双优化（2026-08-28）

SSE 落地后轮询的"实时性职责"已被接管，顺势做两件事：

1. **兜底降频**（ADR-0009）：SSE 健在时兜底轮询 5min → 30min，轮询从主力降级为保险，
   断开自动回全速。取模跳发而非重排定时器，避免连接抖动竞态。
2. **推送调度前沿化**（ADR-0010）：30s 纯防抖改为"前沿立即（距上次推送 >30s）+
   后沿 2s 固定节流微批"。单设备编辑秒级上云，爆发变更（导入/拖拽）不放大请求量。

至此端到端：单设备编辑 → ~1s 上云 → SSE 广播 → 对端 ~1s 可见。

## 演进模式小结

- 每一步都是**先立正确性底座，再叠加速度层**：记录级语义 → 实时信令 → 调度优化；
- 速度层全部设计成"可失效、可降级"（信令丢了走轮询、降频随连接状态回退、
  前沿失败有界重试），故障只影响快慢，不影响对错；
- 新决策落 ADR，本文只补叙事——两者不重复。
