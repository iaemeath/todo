## 模型

- 服务端一张 `snapshots` 表：`(user_id PRIMARY KEY, data TEXT, updated_at)`——每用户**一行**，
  data 是全量数据的整包 JSON（tasks/schedules/settings/theme/usage/todoVisible）。
- 客户端 push：本地全部数据打包成一个 JSON 整体上传，服务端整包覆盖落库。
- 客户端 pull：整包下载，本地整体替换。
- 无记录概念、无冲突裁决、无增量游标、无墓碑——删除就是"包里没有"。

## 运行特征

- 实现极简：一个接口对、一次读写、一个表。
- 冲突粒度 = 整个数据集：两台设备并行使用，后推者整包覆盖前推者，
  对方在间隙里建的任何数据都会被抹掉。
- 每次同步都是全量传输，数据量随使用线性增长。
- 无法表达"删除传播"与"字段级合并"。

## 迁移

v4.5 上线时做了一次性迁移：服务端启动时检测"有快照且该用户尚无 records"则拆包成记录行
（拆包时间作为初始 rev/recv），完成后清空 snapshots 数据（表结构保留作回滚线索）。
