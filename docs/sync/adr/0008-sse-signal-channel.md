# 0008. SSE 实时信令通道：一次性票据认证 + tag 排除自身

- **状态**：已采纳
- **决策时间**：2026-08-28（提交 544f8f5）
- **关联**：server/sync.ts（/events、/sse-ticket）、src/services/syncManager.ts（connectSSE）、deploy/nginx-shiguang.conf

## 背景

多设备感知延迟受制于对方推送节奏（30s 防抖 ~ 5min 兜底）。业内四路线对照
（信令+拉取 / 通道直推数据 / 同步引擎框架 / CRDT）后维持"信令+拉取"路线——
本系统是单用户多设备 + 零依赖服务器 + LWW 已验证形态（详见 evolution.md 第四节）。

## 决定

1. **通道只广播裸信号** `{"type":"changed"}`，不携带数据：合并路径保持 pull 唯一；
   信令可丢可重，丢了退化为轮询语义，无正确性风险。
2. **认证用一次性短时票据**：EventSource 无法携带 Authorization 头、JWT 进 URL 会泄漏日志且可重放
   ——客户端先 `POST /sse-ticket`（正常 requireAuth）领 30s 有效、单次使用的票再建连；
   `/events` 路由必须注册在 `router.use(requireAuth)` 之前。
3. **tag 排除自身**：设备随机 tag 同报于 SSE `?tag=` 与推送头 `x-sync-tag`，
   服务端广播时跳过发起设备（它刚拿到裁决结果，避免自唤回拉）。
4. 客户端**自管退避重连**（1s→60s 封顶，每次重新领票）：EventSource 自带的重连对一次性票
   必然 401，不可依赖；旧版服务端 404 静停。服务端 25s 心跳 + `X-Accel-Buffering: no` 穿透 nginx。

## 后果

- (+) 多设备触达分钟级 → 秒级；服务端仍是无状态哑仓库（票与连接表是易失缓存，重启无害）。
- (+) 信号层故障只影响速度不影响正确性（轮询兜底）。
- (-) 长连接占用 fd 与 nginx worker_connections；多进程部署时进程内存的连接表会使信令
  断裂（退化为轮询，无正确性问题；真到那规模需 sticky 或跨进程广播层）。
- (-) 同设备多标签页各建一条连接（tag 互不相识），靠每用户 8 连接上限兜底。

## 被否决的备选

- **通道直推数据（Firestore 型）**：服务端要按连接追踪投递位点/断线重放/保序，哑仓库变
  有状态投递员；客户端出现第二条合并路径，破坏"pull 唯一入口"铁律。
- **WebSocket**：双向能力用不上（本系统对端只需收信号），协议与重连管理更重。
- **轮询加密拳（缩短兜底间隔）**：实时性靠请求堆出来，服务器负担随设备数线性涨。
