# 0003. settings 字段级记录化、usage 追加型流水

- **状态**：已采纳
- **决策时间**：2026-08 中旬（回填记录）
- **关联**：src/services/syncManager.ts（collectAll/applyUsageRecord）

## 背景

settings 是单对象多字段（主题色/时段/提醒开关……），若整对象作为一条记录同步，
两台设备各改一个无关字段就会互相覆盖——冲突粒度错误。

## 决定

- **settings 按字段记录化**：每个字段一条独立记录（`settings:slotDuration`…），
  字段级 LWW 天然实现"改什么同步什么"。
- **usage（AI 用量流水）按追加型处理**：按 id 幂等 upsert（已存在不回退本地），
  清空场景以 `{deleted:true}` 墓碑按 id 移除；不做差集墓碑。

## 后果

- (+) 两个字段的并行修改互不覆盖；pull 端 settings/meta 有脏保护（本机未推变更不被 clobber）。
- (-) settings 字段越多记录越多（当前 ~20 个，无碍）；新字段零成本自动纳入。
- (-) usage"已存在不覆盖"意味着对端无法修正本机用量记录，语义上按"本地流水即真相"取舍。

## 被否决的备选

- **settings 整对象一条记录**：冲突粒度错误，直接否决。
- **usage 用事件时间排序合并**：追加流水无编辑语义，id 幂等已足够。
