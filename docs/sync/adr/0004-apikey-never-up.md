# 0004. apiKey 永不上云

- **状态**：已采纳
- **决策时间**：2026-08 中旬（回填记录）
- **关联**：src/services/syncManager.ts（collectAll 的 `if (k === 'apiKey') continue`）、ADR-0003 的 kv 持有语义

## 背景

AI 功能的云端 API key 是高价值敏感凭据，同步服务端虽是自用，但数据库泄露/备份外流时
不该连带泄露它；且服务端是"哑仓库"，本无保存密钥的必要。

## 决定

`collectAll()` 收集 settings 时**跳过 apiKey 字段**——它永不出现在同步通道里；
存在于两处：本机 localStorage、导出的备份文件（导入时随备份恢复，旧备份无 key 回退本机现值）。

## 后果

- (+) 数据库/云端泄露面里没有 AI 密钥；服务端继续保持不懂业务。
- (+) 云端恢复（force pull）天然不丢本机 key——云端根本没有这个记录（有单测锁定）。
- (-) 新设备不自动获得 key：需要手动导出/导入一次备份文件，或有 key 的旧设备推过来。
  这是安全换便利的明确取舍。

## 被否决的备选

- **key 加密后上云**：加密密钥还是要放本机，防不了同级别泄露，白增复杂度。
- **key 存服务端按需下发**：与"哑仓库"哲学冲突，服务端从此持有敏感数据。
