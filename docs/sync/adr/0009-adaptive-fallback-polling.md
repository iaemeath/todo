# 0009. 兜底轮询自适应降频：SSE 健在时 5min → 30min

- **状态**：已采纳
- **决策时间**：2026-08-28（提交 76af725）
- **关联**：src/services/syncManager.ts（SSE_FALLBACK_TICKS、interval 回调）

## 背景

SSE 落地后，兜底轮询的"实时性职责"已被接管，但仍以 5min 固定节奏发推拉——
信令正常时这是纯冗余流量；反过来若为省流量拉长间隔，SSE 失效时延迟又不可接受。

## 决定

兜底定时器保持 5min 一跳不变，但**按 SSE 连接状态跳发**：连接对象存在（健在）时每
6 跳才实发一次（= 30min），断开立即回全速。**取模跳发而非重排定时器**——连接状态抖动
不会引发定时器重排竞态。`stopSync` 清零计数。

## 后果

- (+) 信令正常时轮询流量降为 1/6，从主力降级为保险；SSE 失效时自动回到原兜底强度。
- (-) SSE"假死"（TCP 半开未触发 onerror）期间最坏 30min 才兜底一次；缓解因素：
  期间任何一次成功 push 都会顺带 pull，且服务端进程崩溃会关 socket 快速触发重连。
- (-) 客户端无从感知服务端 25s 心跳（SSE 注释帧不触发 onmessage），健康判定只能依赖
  连接对象存在性——半开检测依赖浏览器 TCP 栈，属已知限制。

## 被否决的备选

- **按连接状态重排 setInterval**：重排与连接事件竞态，代码复杂无收益。
- **拉长 SSE 心跳间隔换取假死检测更快**：方向搞反——假死检测靠客户端重连而非心跳。
