# 0005. 数据管理三层模型：本机管用 / 同步管网 / 导出管历史

- **状态**：已采纳
- **决策时间**：2026-08 下旬（回填记录，关联提交 d72281d）
- **关联**：src/components/DataManageTab.vue、src/services/syncManager.ts、CLAUDE.md §4

## 背景

数据管理页曾有一层"本机保护快照"用于撤销误操作，与云同步、导出文件三者语义交叠，
用户（开发者本人）也说不清"恢复"到底恢复到哪——三个覆盖入口互相打架。

## 决定

职责三分，删除快照层：

1. **localStorage 管日常**：运行时唯一主存储，断网完全可用。
2. **同步管网**：登录态下记录自动传播，不提供历史版本。
3. **导出文件管历史**：唯一的"后悔药"——覆盖类操作（文件导入/云端恢复）的警示文案
   均指向"先导出备份"；apiKey 随备份导出导入（ADR-0004）。

## 后果

- (+) 三个入口语义互斥清晰：「从云端恢复」与「文件导入」都是整体覆盖、最后操作说了算，
  且明确警示不要连用。
- (-) 没有自动快照/撤销层：误覆盖且无备份 = 真丢失。以"操作前警示 + 导出习惯"对冲，
  自用规模接受。

## 被否决的备选

- **保留本机快照层做撤销**：与同步基线、导入墓碑三方状态耦合，是历史上数据不一致的来源。
- **服务端版本历史（时间机器）**：需要 records 多版本存储，超出个人项目复杂度预算。
