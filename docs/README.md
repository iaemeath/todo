# 拾光文档中心（docs/）

组织方式：轻量 docs-as-code——文档随代码入库、随提交演进，与代码同review同版本。

## 目录组织原则

1. **按业务域分目录**（如 `sync/`），不按文档类型分顶层——找一个域的全部资料只进一个目录。
2. **域内四类文件，时效性分明**（这是本仓库的核心约定）：

   | 文件 | 时态 | 生命周期 |
   |---|---|---|
   | `current.md` | **现在时** | 无状态说明，只描述"现在是什么"。随代码同步重写，永远可信任，不含任何历史 |
   | `evolution.md` | **过去时** | 演进叙事：每一步为什么变、被什么驱动。只追加新篇章，不改旧篇章 |
   | `adr/` | **决策时** | Architecture Decision Records。**不可变、只增不改**——被推翻时只把 Status 改为"已取代"并指向新 ADR，正文永不动 |
   | `archive/` | **冻结** | 旧版文档的原貌快照，头部注明冻结时间与替代文档，永不再更新 |

3. **路径一律 ASCII，标题用中文**——跨平台 zip 分发 / Syncthing 同步盘 / nginx 静态服务的编码兼容（deploy 层已踩过 zip 编码坑）。
4. **文件名不嵌日期**：时间是 git 的职责（`git log --diff-filter=A` 即创建时间），文件名重复记录违反单一真相源；
   活文档（current/features）带日期会被误读为快照；时序敏感性由编号表达（ADR 的四位序号即时间序）。
   日期写在**文件头元数据**里（ADR 的"决策时间"、冻结档的"冻结说明"、清单的"最后校准"）。
   日期前缀仅适用于"按名排序即时间序"的流水型文件（会议纪要/日志），本仓库暂无此类。
5. ADR 命名 `NNNN-kebab-title.md`（四位零填充，按决策时间排序），格式见 `sync/adr/0000-template.md`。

## 业内主流参照（为什么这样组织）

- **ADR（Michael Nygard, 2011）**：架构决策记录的事实标准，`docs/adr/` 是业界最常见落点。本仓库 `adr/` 即 Nygard 格式的中文精简版。
- **Diátaxis**（教程/操作指南/参考/解释四象限）：面向产品用户的文档站框架（Django、Cloudflare 在用）。本仓库是开发者自用工程文档，取其"按读者需求分型"思想，不搬四象限。
- **docs-as-code**：文档进仓库、走 PR、随代码版本化——本仓库默认即此，无需额外设施。
- **Arc42 / C4**：重型架构文档模板，适合多人大型系统；个人项目照搬是负担，规模化后再考虑。
